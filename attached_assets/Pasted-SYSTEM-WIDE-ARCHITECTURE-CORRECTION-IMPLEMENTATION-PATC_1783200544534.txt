3. SAVED STYLES SYSTEM (CORE ARCHITECTURE)

Definition (CRITICAL)

A Saved Style is NOT an image.

It is only:

- serialized editor objects
- tool properties
- percentage-based positioning
- layer order
- references to persistent assets (e.g. "logo_id")

It must NEVER contain:

- JPG / PNG exports
- binary image data
- flattened canvas snapshots
- uploaded temporary assets
- the workspace image itself

---

Creation Flow

- Must only be accessible from:
  - Settings → Manage Saved Styles
  - + Create New Saved Style (from Saved Styles list page)

Editor Mode:

- Must open on a blank canvas only
- Blank canvas is a workspace only and is NEVER saved

---

Constraints:

- Maximum 10 objects per Saved Style
- Hard block adding the 11th object (no bypass)
- Enforced in real-time during editing

---

Apply Flow:

- Select Saved Style → apply to image
- Reconstruct objects in normal editor
- Continue editing normally afterward

---

Important:

- No separate Saved Style editor system
- Must reuse existing editor with restricted mode only

---

Logo tool MUST be corrected

7. RENDERING + STATE BUG FIX (CRITICAL)

Fix unified layer and rendering pipeline issues:

Problem A:

Filters + paint cause:

- paint color distortion
- recursive filter re-application

Fix:

- Filters must be applied as a single compositing stage
- Painting must NOT re-trigger filter pipeline
- No cumulative filter stacking per stroke

---

Problem B:

Inserted images become duplicated or desynced after painting

Fix:

- Each image must remain a single persistent layer instance
- Paint tool must not clone or detach layers
- Layer registry must remain source-of-truth
- Undo confirms this is state mutation bug, not persistence bug

---

Hard constraints:

- No flattening solution
- No layer duplication workaround
- Must preserve non-destructive editing model
