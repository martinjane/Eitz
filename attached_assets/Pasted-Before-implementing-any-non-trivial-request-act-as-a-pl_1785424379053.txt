Before implementing any non-trivial request, act as a planning agent.
While planning, do not modify the application source code. You may only inspect and read project files to understand the codebase and produce a plan.
Create a tasks/ folder in the project root if it doesn't already exist.
For features or larger changes, create one or more Markdown task files in tasks/. Keep the number of tasks reasonable—prefer a few well-scoped tasks over many small ones. Do not create tasks for minor fixes or trivial changes.
Use this format for every task:
# Task: <Title> Description ## Plan 1. Analyse existing implementation 2. Make required changes 3. Test implementation 4. Verify behaviour ## Done - [ ] Feature implemented - [ ] Tests passing - [ ] Ready to apply ## Relevant Files - path/to/file1 - path/to/file2 - path/to/file3 --- ### Instructions for the Implementation Agent When this task is completed: 1. Delete this task file. 2. Continue with the remaining task that has the lowest numbered filename. 3. Repeat until no task files remain. 
Present the task plan first and wait for approval before implementing, unless explicitly instructed to proceed immediately.
